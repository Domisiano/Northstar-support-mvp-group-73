3. Daily Rules of Engagement & Code Syncs
To satisfy the strict grading audit requirements, our pod must comply with these operational guidelines daily:
•	Mandatory Daily Syncs (9:00 PM EAT): The team will meet briefly every evening at 9:00 PM EAT sharp via WhatsApp and Slack to review blocking issues and align code bases.
•	Immediate Board Card Updates: Task cards must be migrated to the "Done" workspace columns on the exact calendar day the development work happens. Batched end-of-week updates are strictly prohibited.
•	The 4-Hour Micro-Task Ceiling: No individual board task card may exceed 4 hours of total work volume. If a task expands unexpectedly, the owner must split it into discrete sub-task components immediately.
•	Strict Commit Message Format Rules: General save messages such as "wip," "updates," or "bug fix" will cause our team audit log report to fail. Every git code push must use the specific pattern syntax:
<type>: <what changed> - <why it matters>
4. Anti-Ghosting Rules & Escalation Pipeline
As the designated Project Admin, Mr. Elvisio will continually check our team activity indicators. If any member stops participating, the following timeline actions activate:
1. 24 Hours of Inactivity: Mr. Elvisio will issue a direct warning notice via WhatsApp/Slack chat to flag the missing activity markers.
2. 48 Hours of Inactivity: If the member records zero progress updates for two consecutive days, Mr. Elvisio will immediately trigger the formal course instructor escalation pathway to protect the grading scores of the remaining active pod.
5. Definition of Done (DoD) Criteria
A task is not considered finished until it satisfies these checkable metrics:
•	The code logic operates perfectly without crashing the central chat input tray.
•	The script has been uploaded directly to the team's GitHub repository from the owner's personal account.
•	A clean, descriptive, rule-abiding commit message accompanies the update on the audit trail.
